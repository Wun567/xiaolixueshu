# 量化研究与实证分析

适用于数据审计、清洗、建模、诊断与结果报告；与根目录规则共同使用。

## 1. 运行前

读取变量字典、研究设计、既有脚本和分析决策，核实数据权限、输入输出及潜在覆盖操作。原始数据只读，衍生数据另存；沿用项目目录，不为套模板重排文件。

## 2. 分析流程

1. 审计维度、类型、唯一键、缺失、范围、异常、重复、合并匹配率和样本流失。
2. 将清洗与排除规则写入脚本并记录理由；核对单位、反向题、聚合、时间窗口、滞后、固定效应和聚类层级。
3. 按研究设计核实估计方法及适用条件；不凭方法名称套用模型，不为追求显著性试规格或选择性报告。
4. 运行可复现脚本，保存命令、顺序、环境/包版本、适用的随机种子、日志与表图；运行失败如实记录。
5. 针对具体识别威胁安排诊断、稳健性或敏感性分析，保留不一致和不利结果，区分预设与探索分析。

## 3. 结果解释

1. 数字对应实际输出，报告样本、规格、估计与标准误方法、效应大小和适用的不确定性指标；核对正文、表图和附录。
2. 检验通过不等于识别成立，显著不等于重要；因果语言须由设计及识别假设支持，不将统计关联直接写成机制验证。
3. 数据或环境不足时可交付分析计划与代码草稿，明确未在真实数据上验证；模拟结果不得混入正式结果。

## 4. 交付与核验

按需交付脚本、表图、分析说明和复现命令，使用既有目录；新项目可区分 `data_raw/`、`data_processed/`、`scripts/`、`logs/` 与 `outputs/`。

提交前检查数据处理可追溯、主要流程可重跑、输出与正文一致；列明未执行检查及其对当前推论的影响。
